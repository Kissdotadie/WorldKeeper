# 开发约束速查（每次开发先读这份）

> 硬性约束速查。开发时读**本文 + 当前阶段文档**就够，设计与决策记录按需查阅仓库外的项目笔记。

---

## 三条铁律（破一次就回不去）

1. **索引零独占状态** —— 索引只放 Markdown 的派生数据。审核状态、用户偏好、视图装饰一律落文件。只要有一条信息只活在索引里，「删掉索引重建即恢复」就永久失效。
2. **关系真源唯一** —— `[[双链]]` 是实体关系的唯一真源。索引里的关系表只能由它派生，不能反向写入。
3. **出处永不丢失** —— 每条信息必须能追溯到来源：录入方式（手工/规则/AI）+ 时间 + 来源章节与位置（有则记）。

## 用户的硬性约束

- **不接 AI 写正文**：不生成、不续写、不润色、不改写正文任何一字
- **正文区只读**：`chapters/` 目录对工具只读，任何自动更新只写档案文件
- **要用 AI 读正文**：抽取实体 / 关系 / 伏笔 / 事件，产出必须走人工确认
- **AI 可降级**：AI 不可用时工具照常运行，退化为规则抽取
- **协议必须可商用**：禁用 GPL / AGPL / SSPL 等传染性或禁止商用协议
- 中文界面，单用户，本地运行，不做账号体系

## P0 必须落实的口子（第一梯队）

| # | 口子 | 做法 |
|---|------|------|
| 1 | 实体 ID 与文件名解耦 | 稳定 id（如 `char-pei-yuan`），name 与文件名可随意改，**所有引用只认 id** |
| 2 | 每条信息带出处 | frontmatter 携带 `created_at` / `updated_at` / `provenance`(method, sources) |
| 3 | schema 版本号 | 每个实体文件带 `schema_version`，配套迁移脚本 |
| 4 | API 与路径第一参数是 book_id | 数据路径 `data/books/<book_id>/`，路由 `/api/books/{book_id}/...` |
| 5 | 索引零独占状态 | 见铁律 1 |
| 6 | 路径全部走配置 | 三层：全局 `config.yaml` / 书目 `book.yaml` / 用户偏好 `preferences.json`，**无硬编码路径** |

## 安装分发相关口子（P0 全做）

| # | 口子 | 说明 |
|---|------|------|
| A1 | **程序目录 ≠ 数据目录** | 安装目录（Program Files）只读，数据必须放用户可写位置 |
| A2 | 资源路径统一解析器 | 打包后工作目录会变，不能假设 `./data/` 这类相对路径 |
| A3 | 前端静态文件双模式加载 | 开发走 Vite dev server，打包后由 FastAPI 托管 `dist/` |
| A4 | 端口自动探测 | 默认 8765，被占用则自动顺延 |
| A5 | 单实例检查 | 重复启动不要起两个后端抢端口和文件 |
| A6 | 日志落文件 | 写到 `{data_dir}/logs/`，界面里可查看 |
| A7 | 优雅退出 | 退出前先落盘、再关数据库 |

## 预留但 P0 只需留结构

路由分区 `/` `/m` `/admin`（移动端与后台先留空壳）· 快捷键注册层 · 撤销/重做操作栈位 · FTS5 检索 · 文件指纹（检测外部编辑器改动）· 异步任务表 · token 计量埋点

## 关键路径

| 项 | 值 |
|----|-----|
| 程序目录 | 安装版由安装向导决定；源码运行时即仓库根目录 |
| 数据目录 | 可配置（见数据目录里的 `config.yaml`），**不放在程序目录里** |
| Python | 3.11+（本项目在 3.13 上开发与验证） |
| Node | 18+（前端构建用，本项目在 22 上验证） |
| 默认端口 | 8765 |
| 数据库 | SQLite 3.53+（FTS5 + trigram 中文检索可用） |
