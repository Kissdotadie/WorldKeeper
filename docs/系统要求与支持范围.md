# 系统要求与支持范围（N3）

> 用户实测时问过：**「只测了 Win11，那 Win10 支持吗？甚至 Win7？Linux？」**
> 这份文档就是那个问题的完整答案 —— 口径写死在这里，也写死在安装器里。

## 一句话结论

| 系统 | 支持情况 | 说明 |
|------|---------|------|
| **Windows 11 x64** | ✅ 官方支持 | 已实测（VM 干净机器完整闭环通过） |
| **Windows 10 x64** | ✅ 官方支持 | 与 Win11 同为 10.0 内核；安装器允许安装 |
| Windows 8.1 | ❌ 不支持 | 嵌入式 Python 3.13 的底线虽然到 8.1，但我们不承诺、也未经测试 |
| **Windows 7** | ❌ 明确不支持 | 见下 |
| Windows 32 位 | ❌ 不支持 | 包内只有 amd64 的 `python313.dll`，装上也起不来 |
| **Linux / macOS** | ❌ 不承诺 | 见下 |

## 为什么这么定

### Windows 10/11 x64 —— 支持

- **嵌入式 Python 3.13 自带运行时**：不需要用户机器预装任何东西。
  `python313.dll`、`vcruntime140.dll`、SQLite、`zlib` 全部随包内置 ——
  「用户机器零前置依赖」这一点在选型时就赚到了。
- 唯一要求是 64 位（`x64`）。这一点由安装器的 `ArchitecturesAllowed=x64compatible`
  强制，装不上会明确报错，而不是装完闪退。

### Windows 7 —— 明确不支持

不是懒得适配，是**成本与收益不成比例**：

- Python 3.13 官方就不支持 Win7（需要降到 3.8，而 3.8 已停止维护）；
- 降级后要连带处理一大堆兼容改造（老 API、SSL、时区数据等）；
- Win7 早已停止接收安全更新，让一个会读用户小说稿的工具跑在无补丁的系统上也不合适。

安装器用 `MinVersion=10.0` 挡住：Win7 上双击安装包会直接弹
「此程序需要 Windows 10 或更高版本」，**不会**放进去再炸。

### Linux —— 不承诺（但技术上不是死路）

- **托盘启动器是 `ctypes` 直调 Win32**（`user32` / `shell32` / `kernel32`），
  整包不能移植；
- 但**前端是纯 Web、后端是 FastAPI**，本身跨平台。
- 结论：目前不承诺。将来真有需求，单列一期做「Linux 版启动脚本 + 无托盘模式」，
  工作量主要在打包与启动方式，不在业务代码。

## 用户可见的落实点

1. 安装器：`MinVersion=10.0` + `ArchitecturesAllowed=x64compatible`
   —— 不满足条件时**在向导第一步就说清楚**，而不是装完闪退。
2. 这份文档：口径的单一出处，后续宣传/说明文案都引这里。
3. `docs/VM实测-传包与验收清单.md` 的 2.11 项：在旧系统上应看到拒绝安装的提示
   —— 那是有意为之，不是 bug。
